wire_protocol.txt — Driver Station ⇄ Server ⇄ Pi Client (v0.2)

Goal
  Simple JSON protocol over a single WebSocket.
  Supports:
    - low-latency teleop commands (<= 20 Hz)
    - configurable telemetry stream (default 10 Hz)
    - e-stop
    - action queue (drive goals)
    - alerts
    - ownership/mux (teleop vs auton)

 Transport
  WebSocket endpoint: /ws on the driver-station WebSocket port (8766)
  Message encoding: UTF-8 JSON objects, one per WS frame.
  Recommended JSON serialization on sender:
    separators=(",",":")  

Timing / Identity
  ts_ms  : sender timestamp in milliseconds (use monotonic ms if available)
  seq    : per-direction increasing sequence number (optional but strongly recommended)
  id     : request/transaction identifier used for matching responses (hb, queue actions)

Units
  cmd.lx : linear-x, meters/second (m/s)
  cmd.az : angular-z, radians/second (rad/s)
  imu.rpy: roll/pitch/yaw, radians (rad)
  enc.*  : wheel speeds, revolutions/second (rps)
  bat.v  : volts (V)
  bat.i  : amps (A)
  net.*  : kbps, milliseconds

Behavior rules
  - cmd messages should be rate-limited to <= 20 Hz by the client.
  - telemetry frames are pushed by the server at telemetry_hz (default 10 Hz).
  - mux determines who is allowed to command motion.
  - server MAY ignore cmd messages when mux != "teleop".
  - estop is a latch: once asserted, motion should remain stopped until cleared.

# -----------------------------------------------------------------------------
# Client → Server Messages
# -----------------------------------------------------------------------------

1) Heartbeat (client sends ~5 Hz, i.e., every ~200 ms)
  Purpose: detect dead connections + measure RTT (via hb.ack)
{ "t":"hb", "id":421, "ts_ms":12345678 }

2) Teleop command (<= 20 Hz)
  lx: forward/backward speed command in m/s
  az: turn rate command in rad/s
  seq: monotonically increasing integer for debugging and stale-cmd detection
{ "t":"cmd", "seq":812, "ts_ms":12345680, "lx":0.25, "az":-0.30 }

3) Emergency stop (latched)
  value=true  : latch e-stop ON (stop motion)
  value=false : clear e-stop (allow motion if mux permits)
{ "t":"estop", "ts_ms":12345681, "value":true }

4) Set / reconfigure telemetry stream
  telemetry_hz: server push rate for tlm frames
  tlm_fields  : optional allow-list of sub-objects to include in tlm payload
  (useful for bandwidth control and future extensibility)
{ "t":"set", "telemetry_hz":10, "tlm_fields":["imu","enc","bat","net","mux","queue"] }

5) Mux / ownership request (teleop vs auton)
 mode: requested mode. Server decides final mux and broadcasts mux.state.
{ "t":"mux.request", "ts_ms":12345690, "mode":"teleop" }

6) Queue a drive action (goal)
  id: caller-provided identifier for matching queue.result / queue.state
  distance_m: meters to drive
  heading_deg: heading to maintain (degrees)
  max_speed_mps: speed limit (m/s)
{ "t":"queue.drive", "id":"drive-17", "distance_m":1.0, "heading_deg":0, "max_speed_mps":0.4 }

7) Cancel current queue action (and/or clear pending)
{ "t":"queue.cancel", "ts_ms":12345700 }

# -----------------------------------------------------------------------------
# Server → Client Messages
# -----------------------------------------------------------------------------

1) Hello / handshake
  ver: protocol version
  caps: server capabilities (informational)
  defaults: key default rates/limits so clients can adapt automatically
{
  "t":"hello",
  "ver":"0.2",
  "server":"driver-station",
  "caps":["teleop","queue","estop"],
  "defaults":{"telemetry_hz":10,"cmd_hz_max":20}
}

2) Heartbeat acknowledgement (for RTT calculation)
  Client measures RTT = now_ms - hb.ts_ms (or uses echoed timestamps)
{ "t":"hb.ack", "id":421, "ts_ms":12345705 }

3) Mux state broadcast
  mode: current mode authoritative on the server/pi side
  owner: optional human-readable owner label (client id, "pi", etc.)
{ "t":"mux.state", "ts_ms":12345706, "mode":"teleop", "owner":"web" }

4) Telemetry frame (pushed at telemetry_hz, default 10 Hz)
  mux: who owns motion ("teleop" or "auton")
  imu: rpy in radians
  enc: wheel speeds and raw encoder ticks
  bat: battery info
  net: network stats including rtt_ms if computed from hb/hb.ack
  cmd_echo: last accepted command (useful to see what the robot/server is actually using)
#    NOTE:
#      Telemetry values SHOULD come from the rover/pi (authoritative).
#      During development, stubs may fill placeholders, but keep schema stable.
{
  "t":"tlm",
  "seq":9321,
  "ts_ms":12345710,

  "mux":"teleop",

  "imu":{"rpy":[0.02,0.01,1.57]},
  "enc":{"l_rps":1.22,"r_rps":1.19,"ticks":[12345,12312],"hz":100},
  "bat":{"v":11.9,"i":1.2,"temp":32.1},
  "net":{"ctl_kbps":8,"tlm_kbps":22,"vid_kbps":900,"rtt_ms":25},

  "cmd_echo":{"lx":0.25,"az":-0.30}
}

5) Queue state update (event-driven and/or periodically included in tlm)
  active: currently running action with progress [0..1] and remaining distance
  pending: list of queued action IDs
{
  "t":"queue.state",
  "ts_ms":12345720,
  "active":{"id":"drive-17","progress":0.42,"remaining_m":1.10},
  "pending":[{"id":"drive-18"},{"id":"drive-19"}]
}

6) Queue result (completion/failure)
  id: matches the command ID provided by the client
  success: true/false
  reason: human-readable reason (for UI logs)
{ "t":"queue.result", "ts_ms":12345740, "id":"drive-17", "success":true, "reason":"Done" }

7) Alerts / warnings / errors (event-driven)
  level: "info" | "warn" | "error"
  msg: human-readable message
{ "t":"alert", "level":"warn", "msg":"IMU timeout 200 ms" }

# -----------------------------------------------------------------------------
# Suggested defaults (non-binding)
# -----------------------------------------------------------------------------
# - Client heartbeat: 5 Hz (every 200 ms)
# - cmd rate limit: 20 Hz
# - telemetry default: 10 Hz
# - Telemetry fields default: imu, enc, bat, net, mux (queue optional)

# -----------------------------------------------------------------------------
# Extensibility guidance
# -----------------------------------------------------------------------------
# - Add new message types by prefixing with a namespace: "nav.*", "slam.*", "arm.*"
# - Keep old keys stable; add new keys rather than renaming.
# - If adding a compact/high-rate telemetry variant, use a new type "tlm2".
